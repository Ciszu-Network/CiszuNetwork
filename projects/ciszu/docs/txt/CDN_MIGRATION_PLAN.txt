PLAN DE MIGRACIÓN A CDN MULTIMEDIA — Ciszu CDN (Cloudflare R2)
CDN MULTIMEDIA MIGRATION PLAN

[ESPAÑOL]

1. PROBLEMA ACTUAL

El repositorio de Ciszu Network contiene (o referenciaba) assets multimedia pesados:
- GIFs animados
- Videos (MP4, WEBM)
- Imágenes grandes (PNG, JPG de banners, fondos)
- Archivos de música (MP3, OGG, WAV)
- Instaladores EXE (MuzicMania)
- Documentación (PDF, DOCX, MD)

Aunque .gitignore excluye la mayoría (*.gif, *.mp4, *.mp3, etc.),
el contenido referenciado en el código usa rutas locales (public/, content/),
lo que impide:
- Servir assets optimizadamente (sin CDN, sin caché global)
- Mantener el repo liviano si se añadieran nuevos assets
- Sincronizar assets entre versiones (web, desktop, mobile)
- Escalar la distribución de contenido

2. SOLUCIÓN: CLOUDFLARE R2 (Ciszu CDN)

Cloudflare R2 (bucket ciszu-cdn) actuará como CDN multimedia.
Ventajas:
- 10 GB de almacenamiento gratuito
- Sin tarifas de egress (ancho de banda de salida gratuito)
- S3-compatible API (misma librería que AWS S3)
- Edge global de Cloudflare (baja latencia)
- Cache-Control configurable para assets inmutables
- La librería @ciszunetwork/cdn ya tiene assetResolver.resolve() preparado

Supabase Storage queda exclusivamente para contenido generado por usuarios
(avatares, archivos adjuntos en DB). NO para CDN.

3. INFRAESTRUCTURA EXISTENTE

packages/cdn/index.ts:
  resolve(path, { forceCdn, forceLocal }) → resolución híbrida local+CDN
  resolveIcon(name, style, format) → resuelve iconos SVG
  Modos: Tauri (local), desarrollo (local), producción (R2)

scripts/upload-cdn.js:
  Sube assets a Cloudflare R2 usando S3 API (AWS Signature V4)
  Necesita: R2_ACCOUNT_ID, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY
  Comando: pnpm cdn:upload
  Opción: --dry-run para vista previa

scripts/copy-assets.js:
  Fallback offline: copia SVGs críticos a public/ durante prebuild
  Modo normal: solo críticos | --all: todos los assets

assets/:
  Fuente de verdad única para CDN. Estructura trackeada en git con .gitkeep.
  Contenido binario excluido de git por .gitignore global.

4. SISTEMA MIXTO LOCAL + CDN

El AssetResolver implementa una estrategia híbrida:

| Entorno    | forceCdn | forceLocal | Resultado                          |
|------------|----------|------------|------------------------------------|
| Tauri      | —        | —          | tauri://localhost/assets/ (local)  |
| Tauri      | ✓        | —          | CDN (R2)                           |
| Desarrollo | —        | —          | Ruta relativa /path (local)        |
| Desarrollo | —        | ✓          | Ruta relativa /path (local)        |
| Producción | —        | —          | CDN (R2)                           |
| Producción | ✓        | —          | CDN (R2)                           |
| Producción | —        | ✓          | Ruta relativa /path (desde public/)|

El programador elige por llamada:
  resolveIcon('home')                          → automático
  resolveIcon('home', 'outline', 'svg', { forceCdn: true })   → CDN forzado
  resolveIcon('home', 'outline', 'svg', { forceLocal: true }) → local forzado

7. VARIABLES DE ENTORNO REQUERIDAS

R2_ACCOUNT_ID=           # Cloudflare Account ID
R2_ACCESS_KEY_ID=        # R2 API Token Access Key
R2_SECRET_ACCESS_KEY=    # R2 API Token Secret Key
R2_BUCKET=ciszu-cdn      # Nombre del bucket
NEXT_PUBLIC_CDN_URL=     # URL pública (ej: https://cdn.ciszunetwork.com)

8. RIESGOS Y MITIGACIONES

Riesgo: R2 caído o sin conexión
Mitigación: Fallback offline (copy-assets.js) mantiene SVGs críticos locales

Riesgo: Cambio de URLs de CDN en el futuro
Mitigación: assetResolver.resolve() abstrae la URL — solo cambiar en un lugar

Riesgo: Límite de almacenamiento R2 excedido (10 GB免费)
Mitigación: Monitorear uso; comprimir assets; upgrade de plan si necesario
